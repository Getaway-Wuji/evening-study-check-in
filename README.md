# Evening Study Check-in · 晚自习打卡

可供不同班级独立部署的微信公众号 H5 晚自习管理网站。学生打卡、申请请假和查看结果；管理员管理时间、地点、名册、审批和通知。人数由各班自行设置，实际人数随名册自动统计。使用 Next.js 16 和 TypeScript，支持 Vercel 部署。

[Fork 本项目](https://github.com/Getaway-Wuji/evening-study-check-in/fork) · [部署到 Vercel](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2FGetaway-Wuji%2Fevening-study-check-in) · [MIT 许可证](LICENSE)

## 本次已实现

- 蓝色黏土风界面，统一登录、学生端和管理后台；支持手机布局、键盘焦点和减少动态效果偏好。主题说明见 [DESIGN.md](DESIGN.md)。
- 学生端：个人身份、今日打卡、定位及距离校验、照片和证明上传、多日分类请假、撤回、审批进度、历史记录。
- 后台：自定义班级人数上限、名册录入与 CSV 导入、姓名学号编辑、账号重置、考勤明细与人工补录、审批和撤销、考勤导出、通知状态、操作日志。
- 打卡开始、晚自习开始、打卡截止时间由每个班级自行填写。首次初始化设置本班默认时间，之后可按生效日期修改、为某段周次使用独立时间，或临时调整某一天；截止时间包含对应分钟。
- 学期按周一至周日计周，每周上晚自习的星期由管理员选择，不预选固定星期。每个星期可分多段周次，分别设置教室、时间、定位点、半径和材料要求；默认仅收集自动识别的姓名与定位。
- “打卡安排”和“系统设置”直接提供每周星期勾选，自动计算每周天数。移除星期会停用其周次规则，预览发布后更新未来场次，保留历史与单日调整；重新添加星期后可启用原规则。
- 手机端兼容处理和本轮检查范围见 [手机端检查记录](MOBILE-QA.md)，包含尚需微信真机验收的项目。
- 周次规则先保存，再核对实际日期并发布；同星期周次重叠会被拦截。批量发布保留单日临时调整，跳过历史及已开始场次；默认时间更新保留不同周次的教室和独立时间。
- 微信公众号 OAuth 登录、学号姓名核对及关联已有账号；不采集人脸。密码账号可独立使用，同一学生始终对应一个身份。
- 后台时间与范围判定、GCJ-02 坐标统一、规则版本、场次名单、单场签到唯一约束、审批与签到事务互斥。
- 启用邮件通知时，请假与通知任务同时提交；Resend 发送、持久化重试状态、可选 QStash 调度和手动重试。邮件未配置时明确显示待配置。
- 本地文件存储及 Vercel Blob 私有直传，照片与证明的文件数量、单文件大小和证明 PDF 开关由班级设置；校验文件内容和归属，访问经过登录授权。
- 系统设置可新增、改名或停用请假类型，设置说明要求、单次请假场数、请假截止基准与提前分钟数、备注字数、学生说明和邮件通知重试规则。历史申请保留提交时的类型名称。

## 注册与名单核对

登录页入口为“登录”和“注册”。学生注册填写学号、姓名和密码；服务端将学号、姓名与管理员录入的班级名单匹配，符合才注册，同一学号只允许注册一次。姓名以后台名单为准，无需个人绑定码。管理员可编辑姓名和学号，并在核实本人后重置误注册账号，历史考勤继续保留。

姓名与学号不是秘密，这种首次注册方式无法单独防止知情人抢先注册；后续登录由密码或已关联的微信身份验证，遇到误注册由管理员核实处理。

## 每个班级独立部署

本项目采用“一次部署服务一个班级”的方式。不同班级 Fork 后分别使用自己的 Vercel 项目、数据库、私有文件存储、管理员和服务凭据；一个站点内不提供多班级切换。

- 首次初始化可填写班级名称及人数上限，人数上限留空则不设业务人数限制。之后在“系统设置”中修改。
- 实际人数、已注册人数和考勤人数从名册及场次名单统计。填写人数上限不会创建虚构学生，也不会删除已有学生。
- 导入后超出已设置上限会整体拒绝；上限不能少于已有名册人数。每批最多 1000 条、CSV 文件最多 200 KB，可以分批继续导入。
- 更新已有站点时保留原来的人数设置、名单和考勤；已有班级可以在后台调整或取消上限。
- 域名、公众号、邮箱及云端存储均由部署者自行配置。请勿把其他班级的生产数据或密钥复制到自己的部署。

## 本机正式录入

需要 Node.js 22 或更高版本。首次复制 `.env.example` 为 `.env.local`，保留 `DATABASE_URL=file:./data/study.db` 和 `DEMO_MODE=false`，执行 `npm install`、`npm run dev`，打开 http://127.0.0.1:3000/setup 。自行创建管理员账号后，后台按以下顺序设置：

1. 首次初始化填写本班的开始打卡、晚自习开始和打卡截止时间；之后在“打卡安排 → 默认时间与内容”中修改。从受控终端初始化的班级也应在此保存自己的时间。在“设置学期”填写真实学期名称、第 1 周的周一、总周数，自行勾选晚自习星期。
2. 为已选择的各个星期添加周次安排，可按不同周次使用不同教室。每段可沿用默认时间，也可取消“沿用默认打卡时间”后独立填写三个时间；单日调整只影响选中的日期。核对各点坐标，选择定位半径，通常关闭照片和备注。
   修改每周星期可直接在“每周哪些天晚自习”卡片中勾选并保存，再到“每周在哪个教室”核对规则、预览发布。星期仅由学期配置决定，打卡内容模板不再包含旧版固定星期字段。
3. 录入本班学生的姓名、学号，再点击“预览并发布日期”。预览不会修改学生安排，确认发布后才会生成日期；未来未覆盖的日期需要明确确认跳过。
4. 在日历选择某天，可临时改教室、延长截止时间、增加材料或停课，也可恢复对应周次规则。

此模式使用真实时间，数据保存到本机独立数据库；不自动添加虚构人员或考勤。此前的 `data/demo.db` 可单独保留。正式数据模式不代表已部署公网，公众号、邮件和远程文件服务仍需自己的配置。

## 本机演示

需要 Node.js 22 或更高版本。

```powershell
cd evening-study-check-in
npm install
# 首次准备时，复制 .env.example 为 .env.local。
# 使用专用本地演示库，填写：
# DATABASE_URL=file:./data/demo.db
# DEMO_MODE=true
# 可选：DEMO_STUDENT_COUNT=30，生成不同规模的虚构名单。
npm run demo
npm run dev
```

打开 http://127.0.0.1:3000 。登录页有“学生端体验”和“管理后台体验”。演示班级及证明均为虚构数据；演示时间固定为当天 17:45，方便随时验证打卡。只有非生产环境且明确启用 DEMO_MODE 时才可使用演示入口；Vercel 环境强制禁用演示。演示不会发送真实邮件，除非开发者自行填入了真实邮件配置。

已有演示库不会被初始化脚本覆盖。`.local/demo-credentials.json` 仅供本机测试，已被 Git 忽略；不应公开上传。本班真实名单通过后台导入，勿将演示库用于正式服务。

## Vercel 部署

1. Fork 本项目到自己的 GitHub 账号。先创建自己的远程 libSQL 数据库（如 Turso）和 **Private** 类型的 Vercel Blob 存储，准备连接信息；也可通过 Vercel Marketplace 创建这些资源。
2. 将仓库作为项目根目录导入 Vercel，选择 Next.js，构建命令 `npm run build`，不做静态导出。首次部署前按下表填入自己的生产环境变量。
3. 数据库可以使用 `DATABASE_URL`、`DATABASE_AUTH_TOKEN`，或 Turso 集成的 `TURSO_DATABASE_URL`、`TURSO_AUTH_TOKEN`。选择一组实际可用的连接信息即可。**不要把 `.env.example` 中本机用的 `file:` 地址复制到 Vercel**。附件需要 `BLOB_READ_WRITE_TOKEN`，照片和证明直接上传到私有存储。
4. 配置 `APP_URL=https://你的正式域名`、`DEMO_MODE=false` 及随机、保密的 `SETUP_TOKEN`。部署后在自己的 `/setup` 填入初始化凭证，设置班级名称、可选人数上限、本班默认时间及管理员账号；已有管理员时不能再次初始化。也可在受控终端加载 `ADMIN_USERNAME`、至少 14 位的 `ADMIN_PASSWORD`，执行 `npx tsx scripts/setup.ts`，再登录后台设置班级信息。
5. 登录后台录入本班学生的姓名与学号，填写真实学期起点，按星期和周次配置教室及已核对的定位点、半径，再核对并发布日期。
6. 密钥只保存到平台环境变量和受保护的本地配置；不要提交 `.env.local`、数据库、上传文件或测试凭据。初始化后可从 Vercel 运行时环境移除 `SETUP_TOKEN` 和 `ADMIN_PASSWORD`。

平台连接使用项目所有者自己的账号和受保护的环境变量。正式库和文件服务的大陆网络可达性、备份及恢复应在开始收集真实班级数据前实测。

| 生产环境变量 | 用途 |
| --- | --- |
| `APP_URL` | 自己网站的完整 HTTPS 地址 |
| `DEMO_MODE=false` | 正式环境不启用演示入口或模拟时间 |
| `SETUP_TOKEN` | 仅自己掌握的随机初始化凭证，不是学生注册密码 |
| `TURSO_DATABASE_URL`、`TURSO_AUTH_TOKEN` | 自己的 Turso 数据库连接，或改用 `DATABASE_*` 对应变量 |
| `BLOB_READ_WRITE_TOKEN` | 自己的 Private Blob 读写凭据 |

域名可使用 Vercel 提供的地址，也可绑定自己的域名。使用 Cloudflare 时，按 Vercel 给出的实际记录配置 CNAME，先采用 DNS only；无需转移域名注册商。`vercel.json` 默认把应用函数放在东京，可根据数据库所在区域自行修改。普通 Cloudflare DNS 托管不等同于大陆专线或中国节点，访问效果应在实际网络测试。参考 [Vercel 的代理配置说明](https://vercel.com/kb/guide/can-i-use-a-proxy-on-top-of-my-vercel-deployment)、[Cloudflare 中国网络说明](https://developers.cloudflare.com/china-network/)。

公众号登录和真实邮件发送是独立配置项，详见下文；仅部署网站不会自动获得这些服务权限。若使用预览部署，请为其配置独立测试数据和存储，不要连接真实班级的生产数据库。

## 微信公众号接入

本项目目标是 **微信公众号内打开网页**，不包含小程序代码或 web-view 容器。

1. 核查实际公众号是否具有网页授权（`snsapi_base`）和需要的 JS-SDK 接口权限。类型、认证状态和当前开放能力以该公众号后台为准；暂不具备时可先使用学号和密码登录。
2. 配置公众号的 `WECHAT_APP_ID`、`WECHAT_APP_SECRET`，两者均仅在服务器使用。`APP_URL` 必须是最终 HTTPS 域名。
3. 在公众号后台配置网页授权域名和 JS 接口安全域名。将平台提供的校验文件通过 `WECHAT_VERIFY_FILENAME`（例如 `MP_verify_abc123.txt`）与 `WECHAT_VERIFY_CONTENT` 提供在网站根目录，或将原文件放入 `public/`。内容必须与平台给出的原始文件一致。
4. 公众号菜单“晚自习打卡”指向 `https://你的域名/wechat`。网页授权已配置时进入微信身份流程，未接通时保留学号密码入口。授权后填写学号和姓名，与后台名单一致才允许关联身份；已注册密码账号的同学可切换“关联已注册账号”，同时用原密码确认关联。
5. OAuth 使用随机 state 和 HttpOnly Cookie 校验回调，OpenID、授权密钥和接口票据不下发到网页。本站会话为随机令牌，数据库中仅存令牌摘要。
6. 通过 `WECHAT_OAUTH_ENABLED` 与 `WECHAT_LOCATION_ENABLED` 分别启用已确认的能力。微信中优先尝试已配置的 JS-SDK 定位，技术故障或精度缺失时回退至系统定位并标注来源；用户主动取消或拒绝权限时不自动再次请求。后台统一坐标系后计算距离，iOS、Android 微信均须真机验证。
7. JS-SDK 票据使用数据库缓存和 `stable_token`。如果公众号要求调用来源 IP 白名单，而 Vercel 出网地址不稳定，需要选择能提供固定出口的接入方式，或调整托管架构；本项目未假定动态出口能直接通过白名单。

详细配置与验收见 [公众号接入指南](WECHAT-SETUP.md)。后台“系统设置 → 公众号接入”可查看配置及检测服务器票据连接；检测通过不代表微信客户端已验收。

参考官方资料：[公众号接入及网页授权](https://docs.cloudbase.net/integration/wechat-official-oauth)、[公众号域名设置](https://cloud.tencent.com/document/practice/1301/100434)。

## 邮件与重试

- 设置 `RESEND_API_KEY`、已验证发件人的 `MAIL_FROM`；在系统设置保存管理员收件邮箱，可添加多个。邮件通知可由本班后台启用或停用，停用时请假照常保存。
- 学生提交后，申请、附件关联和已启用的邮件任务在同一事务内保存，首次发送会被等待执行。通知包含姓名学号、请假类别、具体原因、日期与教室；普通 JPG、PNG、PDF 证明作为真实附件发送，学生端会说明这一用途。
- 邮件附件原始总量最多 24 MiB，为服务商的编码后体积限制留出余量。超出预算的文件逐项标明，并保留需登录后台的原件链接；原始私有文件不会被公开。发送时才读取私有存储并编码，不把真实附件 Base64 重复写入数据库。
- 发送使用固定通知编号作为幂等键，重试使用同一内容。服务商“已接收”不等于已经阅读；本版不声称已经接入退信或送达回执。
- 自动重试可设置 `QSTASH_TOKEN`、`CRON_SECRET` 和正式 HTTPS `APP_URL`；QStash 调用 `/api/jobs/email` 时带独立授权，失败重试间隔与自动尝试次数由“系统设置 → 班级业务规则”配置；初始值为 1、5、15、60、180 分钟、最多 5 次（包含首次发送）。间隔列表用完后沿用最后一项，达到上限后停止自动发送，管理员仍可手动重试。
- 不使用 QStash 时，请为 `/api/jobs/email` 配置独立调度，并带 `Authorization: Bearer <CRON_SECRET>`。不要仅依赖进程内计时器。Vercel Hobby 的每天一次 Cron 不足以保障分钟级重试。
- QStash 分区域配置时填写控制台给出的 `QSTASH_URL`。后台“建立定时检查”会创建本网站专用的补捞计划（默认每 5 分钟，可通过 `MAIL_SWEEP_CRON` 配置），恢复唤醒失败或租约过期的到期通知；已接收邮件不会被再次发送。
- 后台可运行“测试自动重试（含图片）”：首次调度回调模拟 503，约 10 秒后由 QStash 自动重投，再发送虚构邮件及 PNG。显示实际回调次数、状态和上次自动检查，不创建真实学生或请假。完整免费接入及额度说明见 [MAIL-SETUP.md](MAIL-SETUP.md)。
- 极端网络情况和服务商幂等期限外的人工重试仍可能造成重复邮件，申请编号可识别同一申请。
- “系统设置 → 请假邮件通知”显示实际发件人、管理员收件人和自动重试状态，并可发送一封含虚构原因及 PNG 图片的测试邮件。测试不新增学生或真实申请；已配置私有附件存储时，还会验证测试图片的私有上传与读取，并清理专用测试文件。
- 收件地址、邮件正文和证明摘要在首次生成邮件时形成快照，重试保持内容一致；修改邮箱或类别名称只影响新生成的通知。邮件服务商“已接收”不能当作已经进入管理员收件箱，需实际检查收件箱/垃圾邮件或服务商投递记录。

参考：[Vercel 运行环境](https://vercel.com/docs/functions/runtimes)、[私有文件存储](https://vercel.com/docs/vercel-blob/using-blob-sdk)、[Turso 客户端](https://docs.turso.tech/sdk/ts/reference)。

## 使用边界与后续上线核对

位置判定只能说明提交坐标处于范围内，不能识别楼层、保证实际本人到场或完全阻止虚拟定位。相机入口优先调用相机，但网页文件输入无法保证所有设备都禁止相册。人脸识别、持续轨迹、自动证明鉴真、签退和多班级均不在本版范围。

后台暂无自动过期清理界面；正式运营前需要确定照片、证明、考勤和日志的保留期限，并安排受控的定期清理与备份恢复。未完成真实公众号授权、微信真机定位、私有远程上传、真实邮件收发及大陆校园网络测试前，不能把本地验收等同于正式上线验收。

- `lib/setup.ts`：真实班级首次初始化，不使用演示数据。
- `lib/db.ts`：数据库初始化与事务。
- `lib/wechat.ts`、`lib/mail.ts`、`lib/files.ts`：公众号、邮件与私有文件接入。
- `scripts/`：正式初始化、本地虚构数据及接口验收。
- `tests/`：核心规则与事务测试。
